# ESP32-S3R8 板级基线

本文是本仓库所构建的 ESP32-S3R8 掌机的工程参考，记录已确认的板级事实、由此决定的固件做法，以及仍然需要上板实测的项目。

- 固件事实来源：[`components/bsp/include/bsp_pins.h`](../../components/bsp/include/bsp_pins.h)。
- 下面的引脚事实来自板厂引脚图；画面、声音与电源结果单独记录在文末的验收表里，不能相互替代。
- 最后更新：2026-10-09。

## 1. 硬件基线

```text
ESP32-S3-WROOM-1 / WROOM-1U（ESP32-S3R8：16MB Flash + 8MB Octal PSRAM）
├─ ST7789/ST7789P3 LCD（240x320，SPI2，只写）
│  ├─ GPIO11 -> SCLK
│  ├─ GPIO12 -> MOSI
│  ├─ GPIO10 -> CS
│  ├─ GPIO9  -> DC
│  ├─ GPIO47 -> RST
│  └─ GPIO13 -> BCKL，低电平点亮
├─ 六个按键（低电平按下，内部上拉）——本板没有独立的 OK 键
│  ├─ GPIO38 -> UP     GPIO21 -> DOWN
│  ├─ GPIO39 -> LEFT   GPIO14 -> RIGHT
│  ├─ GPIO16 -> A      GPIO8  -> B
├─ 可选 I2S0 功放输出（无 codec、无 MCLK）
│  ├─ GPIO42 -> WS/LRCK
│  ├─ GPIO41 -> BCK
│  └─ GPIO40 -> DATA/DOUT
├─ 可选 I2S1 ZTS6672 麦克风（板上预留）
│  ├─ GPIO17 -> WS/LRC
│  ├─ GPIO18 -> BCK
│  └─ GPIO4  -> DATA/DIN
├─ 电池采样：VBAT -- 200K -- GPIO1(ADC1_CH0) -- 200K -- GND
│  └─ 1:1 分压，引脚上是电池电压的一半
└─ 板上没有 I2C 从设备（既无音频 codec，也无电量计芯片）
```

| 子系统 | 器件或方式 | 资源 | 固件支持情况 |
| --- | --- | --- | --- |
| MCU | ESP32-S3R8 | 16MB Flash、8MB Octal PSRAM | 已配置（`sdkconfig.defaults`） |
| 显示 | ST7789/ST7789P3，240 × 320，RGB565 | SPI2，40MHz，mode 0 | `bsp_display.c` |
| 背光 | LCD LED，**低电平点亮** | GPIO13，LEDC 5kHz/10bit | PWM 调光；BSP 内部把百分比反相 |
| 按键 | 六个独立 GPIO 按键（无 OK 键） | GPIO 38/21/39/14/16/8 | `bsp_button_gpio.c` |
| 音频输出 | 直连 I2S 功放（无 codec） | I2S0 发送：BCLK 41 / WS 42 / DOUT 40 | `bsp_audio_i2s_out.c` |
| 音频输入 | ZTS6672 麦克风焊盘（板上预留） | I2S1 接收：WS 17 / BCK 18 / DIN 4 | 无驱动；`bsp_audio_read()` 返回 `ESP_ERR_NOT_SUPPORTED` |
| 电池 | 无电量计芯片；1:1 分压进 ADC 引脚 | VBAT — 200K — GPIO1(ADC1_CH0) — 200K — GND | `bsp_battery_adc.c` + `bsp_battery_math.c` |
| I2C | 无总线设备 | —— | `bsp_none.c` 里的降级实现 |
| 控制台 | USB Serial/JTAG | 原生 USB，GPIO19/20 | `CONFIG_ESP_CONSOLE_USB_SERIAL_JTAG` |

| 47 | LCD RST | 输出 | 硬件复位 |

需要留意的保留/风险引脚：

- GPIO35/36/37 在模组内部连接 Octal PSRAM，不能当普通 IO。
- GPIO39/40/41/42 是原生 JTAG 引脚。本板四个都用掉了，因此无法外接 JTAG 调试，请用 USB Serial/JTAG。
- GPIO0/3/45/46 是 strapping 引脚，本基线不分配给外设。
- GPIO19/20 承载原生 USB D−/D+。
- GPIO4/17/18（麦克风）与 GPIO40/41/42（功放）是音频预留脚。BSP 只初始化 I2S0 发送；
  麦克风那几个脚在派生工程启用前不归任何模块所有，启用后应同步更新上面的归属表。
- GPIO39/40/41/42 本身就是 JTAG 脚，意味着功放预留与 JTAG 共用同一组引脚：
  要接外部 JTAG 调试，必须先重新规划这些信号。

### 2.1 外设所有权与共存关系

| 资源 | 所有者 | 共享规则或冲突 |
| --- | --- | --- |
| SPI2 | 显示 BSP | 独占给 ST7789；未配置 MISO。 |
| LEDC 低速定时器 0 / 通道 0 | 背光 BSP | 新增 PWM 使用者请另选定时器/通道。 |
| I2S0 发送 | 音频 BSP | 只发不收；没有可共享的接收通道。 |

| GPIO 38/21/39/14/16/8 | 按键 BSP | 六键配置为"上拉输入、无中断"，由 button 组件轮询判定。 |

| USB Serial/JTAG | 控制台配置 | 日志、烧录、监视共用同一条通道。 |

## 3. 显示

面板用 `esp_lcd` 的 ST7789 厂商驱动、SPI mode 0、RGB565 驱动，外加 `bsp_display.c` 中维护的面板厂商初始化序列与 `0x21` 反色：

- 复位脚真的接了（GPIO47），所以 `esp_lcd_panel_reset()` 走硬件复位。
- 时钟取 40MHz（板厂验证过的值）。提频能提高帧率，但必须先在实机上确认无花屏、无偏色再改。
- 背光低电平点亮：`bsp_display_backlight(percent)` 会把占空比反相，初始化和 deep sleep 用的"灭"电平是 1 而不是 0。
- 应用不使用 LVGL：往内部 RAM 画布自绘，只把变化的矩形通过 SPI 推给面板。
- 屏幕四角是直角：`BSP_LCD_CORNER_RADIUS` 为 0，应用不做圆角遮罩，整块 240 × 320 都显示内容。

换屏后若画面呈负片，把 `bsp_pins.h` 的 `BSP_LCD_INVERT_COLOR` 改成 0；若"亮度 0 最亮"，
说明这块屏不是低电平点亮，把 `BSP_LCD_BL_ACTIVE_LOW` 改成 0。

**渐变与色阶。** RGB565 每通道只有 5/6 位，天空/草坪这种长渐变必须抖动；抖动像素的总数由量化
误差决定，能选的只有【分布】。应用把每行算成"基准档位 + 占空比"（占空比等于该行的量化余量，
见 `main/chick_gradient.c`，掩码见 `main/chick_dither.c`），因此**每行的平均值精确等于理想渐变**，
不存在"平均亮度跳一档"的行。具体哪些像素进位由生成的 32x32 蓝噪声掩码决定
（void-and-cluster，见 `tools/generate-dither-mask.py`）：阈值在空间上打散、低频能量低，
残余误差看起来是细颗粒而不是网格。

有两版做法在实机上被否掉，不要再走回去：

1. 用 4x4 有序矩阵对每一行抖动 → 天空出现块状颗粒、草坪出现每 4 行一条的横纹；
2. 只在量化台阶附近的窄带里抖动、其余行全平 → 平坦区之间的 1 LSB 落差变成明显的大条分层，
   比它想解决的颗粒更糟。

主机测试钉住的性质：端点行取最接近的可表示色、行平均与理想渐变偏差小于 1/256 档、
每通道平均单调、相邻行平均最多差一档、掩码是 0..1023 的排列且没有小周期重复、
通道进位不会溢出到相邻通道。

**白点/色温。** 本批屏的白点偏冷（白偏蓝），这是面板与背光 LED 的固有特性，不是固件问题。
由于本应用的渲染由自己掌控，它在推屏的唯一汇聚点做逐通道增益补偿
（`main/chick_color.c`）：把 RGB565 逐通道展开 → 乘 Q8 增益（抬红、压蓝、绿色不动）
→ 夹回 5/6/5 位。乘性增益保证黑色仍是黑色，背景不会发灰。强度就是设置页里的
`色温`（0 = 不处理，100 = 最暖预设，R×1.055 / B×0.875），可在设备上现场调整，
不需要为每块屏重新编译。两条性质由主机测试钉死：暖度 0 在全部 65536 个 RGB565 取值上
严格恒等，查表结果与逐像素直接计算永远一致。

## 4. 按键

六个独立按键，内部上拉、低电平有效。**本板没有 `OK` 键**：物理丝印只有 上、下、左、右、A、B。
BSP 把它们映射成语义键，应用不依赖丝印：

| 语义键 | 物理键 | GPIO | 在"小鸡快跑"里的作用 |
| --- | --- | --- | --- |
| `BSP_BTN_UP` | UP | 38 | 跳跃；菜单上移 |
| `BSP_BTN_DOWN` | DOWN | 21 | 滑铲；菜单下移 |
| `BSP_BTN_A` | A | 16 | 确定/开始；游戏中跳跃 |
| `BSP_BTN_B` | B | 8 | 返回；游戏中暂停/继续 |
| `BSP_BTN_LEFT` | LEFT | 39 | 标题页切换模式；设置页减小数值 |
| `BSP_BTN_RIGHT` | RIGHT | 14 | 标题页切换模式；设置页增大数值 |

当前应用的界面操作：

| 页面 | 操作 |
| --- | --- |
| 标题页 | 上/下/左/右 切换玩法模式；A 开始；长按 A 或按 B 进设置 |
| 游戏中 | 上 或 A 跳跃；下 滑铲；B 暂停 |
| 暂停页 | A 继续；B 返回首页 |
| 结算页 | A 再玩一次；B 返回首页 |
| 设置页 | 上/下 切换项目（亮度/音量）；左/右 调整数值（长按快速调整）；A 或 B 返回 |

选词与行为由 `BSP_BTN_HAS_B`（即 `BSP_BTN_COUNT >= 6`）决定 —— 这是“按键能力”判断，不是板名判断。

判定时序由 BSP 显式下发：短按窗口 180ms、长按门限 500ms（`BSP_BTN_SHORT_PRESS_MS`、
`BSP_BTN_LONG_PRESS_MS`），不受 button 组件 Kconfig 默认值影响。本板没有电阻梯分压节点，
因此 `bsp_button_read_mv()` 恒返回 -1。

## 5. 音频输出

本板没有音频 codec，MCU 以 I2S 主机方式直接驱动功放：Philips 标准模式、16bit、不使用 MCLK。

| 项目 | 取值 | 理由 |
| --- | --- | --- |
| 端口 | I2S0，仅主机发送 | 板上没有采集通路 |
| 引脚 | BCLK 41、WS 42、DOUT 40 | 板级接线 |
| MCLK | 不使用 | 功放不需要主时钟；不接反而少一路噪声源 |
| 采样格式 | 16bit，按立体声输出 | 源是单声道；两个槽位都给数据，取左声道或取均值的功放都能用 |
| 音量 | BSP 内做数字增益 | 没有硬件音量寄存器 |
| 功放使能 | 未接（`BSP_I2S_PA_CTRL = -1`） | 定型板若加了使能脚，填该 GPIO 即可 |

音频失败不会拦住启动：功放没贴时 I2S 照样初始化成功，游戏静音运行。

## 6. 电量采样

本板没有电量计芯片：电池电压经两颗 200K 电阻 1:1 分压后进 GPIO1（ADC1_CH0），
引脚上是电池电压的一半。满电 4.1V，可用空电点 3.3V。

一次读取的完整链路（每一步都有主机测试）：

| 步骤 | 实现 | 为什么 |
| --- | --- | --- |
| 1. 采样 | 16 次 ADC 采样、12dB 衰减、曲线拟合校准 | 1:1 分压下满电仅 2.05V，远在约 3.1V 量程内 |
| 2. 合理性过滤 | 丢弃落在合理区间（`BSP_BATT_VBAT_MIN_MV`…`MAX_MV`，2.5–4.4V）之外的采样 | 耦合干扰会被读成 5V+ 的不可能电池电压；滤波只能减弱它，不能消除它 |
| 3. 去极值平均 | 排序后丢掉最高/最低 quarter，对中间一半取平均 | 去掉孤立尖峰（例如背光 PWM 边沿耦合） |
| 4. IIR 平滑 | 跨次调用 `值 += (新值 - 值) / 8`（`BSP_BATT_IIR_SHIFT`） | 抑制慢抖动与负载跳变；防抖必须依赖历史值 |
| 5. 分压还原 | `Vbat = Vpin × (Rtop + Rbottom) / Rbottom × 标定系数` | 200K/200K → ×2；`BSP_BATT_MV_SCALE_PPM` 是标定系数 |
| 6. 电压→电量 | 分段线性表：4.10V = 100%，3.30V = 0% | 3.9–3.7V 平台段必须比直线更密才能用 |
| 7. 百分比滞回 | 变化不足 2% 就不更新（`BSP_BATT_SOC_HYSTERESIS`） | 避免图标在相邻两档之间反复闪 |

已知的精度限制与对应做法：

- **源阻抗。** 分压的戴维南等效阻抗是 100kΩ，对 S3 的 SAR ADC 来说偏高：
  采样电容充不满，读数会系统性偏低且抖动。缓解手段就是上面的平均、标定系数，
  以及硬件上在 GPIO1 对地并一颗 100nF（既滤波又给采样电容补电荷）。
- **标定。** `bsp_pins.h` 里的 `BSP_BATT_MV_SCALE_PPM`（默认 1000000 = 不修正）。
  用万用表量电池电压，和串口每 60s 打印的 `电量 %d%%,电压 %d mV` 对比，
  按 `实测 / 读数 × 1000000` 填入。**请用电池供电时标定，不要插着 USB 充着电标。**
- **充电中。** 插 USB 时引脚通常读到的是充电电压，百分比会偏乐观；这个数字在电池供电时才有意义。
- **不做负载补偿。** 重载时端电压会被拉低，临近空电时负载下的读数会偏高几个百分点。
- 电压窗口与曲线分别在 `bsp_pins.h` 和 `bsp_battery_math.c`；换电池体系或改低压保护值时改这两处。

## 7. Flash、PSRAM 与分区

- Flash：16MB，`CONFIG_ESPTOOLPY_FLASHSIZE_16MB`，镜像头固定容量（不做 detect）。
- PSRAM：8MB Octal（`CONFIG_SPIRAM_MODE_OCT`，80MHz）。模组必须是 R8；配置与硬件不符时直接启动失败，而不是悄悄降级到内部 RAM。
- 分区表：`partitions.csv` —— `nvs` + `phy_init` + 一块占满其余 15MB 的 `factory` 应用，不预留 OTA 槽。
- 控制台：GPIO19/20 上的 USB Serial/JTAG，不用 UART0。

## 8. 构建、烧录与验证

本仓库的目标是 ESP32-S3，由 `sdkconfig.defaults` 与 `partitions.csv` 配置。

```bash
# S3R8（默认）：16MB Flash + 8MB Octal PSRAM
./tools/validate.sh                  # 静态检查 + 主机测试 + 固件构建
idf.py -p /dev/cu.usbmodem* flash    # 分段烧录：保留 NVS 内容

# ESP32-S3R8
```

整包 `build/PockiGo-full.bin` 从 `0x0` 写入时会用填充字节覆盖镜像之间的空隙，
包括 NVS 区；需要保留存档时请用分段 `idf.py flash`。详见
[固件布局](../development/engineering/firmware-layout.zh_CN.md#烧录与已存数据)。

## 10. 故障速查

| 现象 | 优先检查 |
| --- | --- |
| 黑屏 | GPIO13 背光电平（低电平点亮）、GPIO47 复位、11/12/10/9 的 SPI 接线、3.3V |
| 亮度反向（0 最亮） | `BSP_LCD_BL_ACTIVE_LOW` 与板子不符 |
| 画面发白或负片 | SPI mode 0、40MHz、RGB565 字节序、`BSP_LCD_INVERT_COLOR` |
| 日志说检测到 16MB Flash，但跑的是 8MB 分区布局 | `sdkconfig` 是别的目标留下的：删掉后重新构建 |
| 启动在 `esp_psram` 处中止 | 模组不是 R8/OCT PSRAM，而配置里开了 `CONFIG_SPIRAM_MODE_OCT` |
| 没碰就触发按键，或两个键同时触发 | 板上缺上拉、按键短路或接到别的 GPIO；对照运行时打印的 GPIO 电平日志 |
| 四角仍有黑色弧形 | `bsp_pins.h` 里 `BSP_LCD_CORNER_RADIUS` 不是 0（或构建产物是旧的） |
| 电量恒为 0% / 100% / 不可能的电压 | 查 GPIO1 分压电阻、`BSP_BATT_DIVIDER_R_*`；合理性过滤会把不可能的值当无效，一直无效就显示 -1（不显示电量槽） |
| 电量百分比整体差一个固定比例 | 用万用表实测后改 `BSP_BATT_MV_SCALE_PPM`；必须在电池供电时标定 |
| 电量百分比来回跳 | 增大 `BSP_BATT_IIR_SHIFT`（更平滑）或增大 `BSP_BATT_SOC_HYSTERESIS`；并在 GPIO1 加 100nF |
| 日志显示"音频就绪"但没声音 | 功放供电/使能、DATA/BCLK/WS 接线，或功放未贴装 |
| 完全没有串口输出 | 板子可能用的是 USB-UART 桥而不是原生 USB：把控制台切到 UART0（GPIO43/44） |
